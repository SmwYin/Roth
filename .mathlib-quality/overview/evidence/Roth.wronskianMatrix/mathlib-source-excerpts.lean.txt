14: # Wronskian of a pair of polynomial
15: 
16: This file defines Wronskian of a pair of polynomials, which is `W(a, b) = ab' - a'b`.
17: We also prove basic properties of it.
18: 
19: ## Main declarations
20: 
21: - `Polynomial.wronskian_eq_of_sum_zero`: We have `W(a, b) = W(b, c)` when `a + b + c = 0`.
22: - `Polynomial.degree_wronskian_lt_add`: Degree of Wronskian `W(a, b)` is strictly smaller than
23:   the sum of degrees of `a` and `b`
24: - `Polynomial.natDegree_wronskian_lt_add`: `natDegree` version of the above theorem.
25:   We need to assume that the Wronskian is nonzero. (Otherwise, `a = b = 1` gives a counterexample.)

15: # Matrices
16: 
17: This file defines basic properties of matrices up to the module structure.
18: 
19: Matrices with rows indexed by `m`, columns indexed by `n`, and entries of type `α` are represented
20: with `Matrix m n α`. For the typical approach of counting rows and columns,
21: `Matrix (Fin m) (Fin n) α` can be used.
22: 
23: ## Main definitions
24: 
25: * `Matrix.transpose`: transpose of a matrix, turning rows into columns and vice versa
26: * `Matrix.submatrix`: take a submatrix by reindexing rows and columns
27: * `Matrix.module`: matrices are a module over the ring of entries
28: * `Set.matrix`: set of matrices with entries in a given set
29: 
30: ## Notation
31: 
32: The scope `Matrix` gives the following notation:
33: 
34: * `ᵀ` for `Matrix.transpose`
35: 
36: See `Mathlib/LinearAlgebra/Matrix/ConjTranspose.lean` for
37: 
38: * `ᴴ` for `Matrix.conjTranspose`
39: 
40: ## Implementation notes
41: 
42: For convenience, `Matrix m n α` is defined as `m → n → α`, as this allows elements of the matrix
43: to be accessed with `A i j`. However, it is not advisable to _construct_ matrices using terms of the
44: form `fun i j ↦ _` or even `(fun i j ↦ _ : Matrix m n α)`, as these are not recognized by Lean
45: as having the right type. Instead, `Matrix.of` should be used.
46: -/

22: # Linear maps and matrices
23: 
24: This file defines the maps to send matrices to a linear map,
25: and to send linear maps between modules with a finite bases
26: to matrices. This defines a linear equivalence between linear maps
27: between finite-dimensional vector spaces and matrices indexed by
28: the respective bases.
29: 
30: ## Main definitions
31: 
32: In the list below, and in all this file, `R` is a commutative ring (semiring
33: is sometimes enough), `M` and its variations are `R`-modules, `ι`, `κ`, `n` and `m` are finite
34: types used for indexing.
35: 
36: * `LinearMap.toMatrix`: given bases `v₁ : ι → M₁` and `v₂ : κ → M₂`,
37:   the `R`-linear equivalence from `M₁ →ₗ[R] M₂` to `Matrix κ ι R`
38: * `Matrix.toLin`: the inverse of `LinearMap.toMatrix`
39: * `LinearMap.toMatrix'`: the `R`-linear equivalence from `(m → R) →ₗ[R] (n → R)`
40:   to `Matrix m n R` (with the standard basis on `m → R` and `n → R`)
41: * `Matrix.toLin'`: the inverse of `LinearMap.toMatrix'`
42: * `algEquivMatrix`: given a basis indexed by `n`, the `R`-algebra equivalence between
43:   `R`-endomorphisms of `M` and `Matrix n n R`
44: 
45: ## Issues
46: 
47: This file was originally written without attention to non-commutative rings,
48: and so mostly only works in the commutative setting. This should be fixed.
49: 
50: In particular, `Matrix.mulVec` gives us a linear equivalence
51: `Matrix m n R ≃ₗ[R] (n → R) →ₗ[Rᵐᵒᵖ] (m → R)`
52: while `Matrix.vecMul` gives us a linear equivalence
53: `Matrix m n R ≃ₗ[Rᵐᵒᵖ] (m → R) →ₗ[R] (n → R)`.
54: At present, the first equivalence is developed in detail but only for commutative rings
55: (and we omit the distinction between `Rᵐᵒᵖ` and `R`),
56: while the second equivalence is developed only in brief, but for not-necessarily-commutative rings.
57: 
58: Naming is slightly inconsistent between the two developments.
59: In the original (commutative) development `linear` is abbreviated to `lin`,
60: although this is not consistent with the rest of mathlib.
61: In the new (non-commutative) development `linear` is not abbreviated, and declarations use `_right`
62: to indicate they use the right action of matrices on vectors (via `Matrix.vecMul`).
63: When the two developments are made uniform, the names should be made uniform, too,
64: by choosing between `linear` and `lin` consistently,
65: and (presumably) adding `_left` where necessary.
